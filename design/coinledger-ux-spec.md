# 藏币录 · 体验设计规范（Phase 2）

> 版本 v1.0 ｜ 适用范围：微信小程序 `miniprogram/`（信息架构 / 交互流程 / 状态反馈 / 无障碍）
> 承接基线：`design/coinledger-visual-direction.md`（Phase 1 视觉方向）+ `miniprogram/app.json` 与各页 `.wxml` 真实结构 + `public/app.js` 共享算法
> 设计基准：750rpx ｜ 术语：**套**（实物成套，整卷 20 枚或套系声明件数）、**份 / rolls**（持仓拥有的套数）、**参考估值**（非成交价）

## 0. 本文定位与承接声明

### 0.1 不越界

本文件只定义**体验与交互**。以下 Phase 1 决策为既定前提，本文一律承接、不重定义、不推翻：

| 承接项 | Phase 1 结论 | 本文如何使用 |
|---|---|---|
| 双皮肤令牌 | 浅色暖白 `#f6f4ef` / 深色复用网站端 `#0a0c10` | 交互状态只引用语义令牌，不写死 HEX |
| 品牌金阶梯 | 10 级 `--cl-brand-50…900`，核心 `#9a6b1f` | 选中态 / 主操作 / 进度统一取 `--cl-brand` |
| 价格红线 | 价格是「参考估值」；红绿只用于带「较上次」标注的变化幅度 | 价格呈现顺序与标注层级见 §4.5、§7 |
| 母题 | 方孔圆钱 SVG（线稿 / 实心 / 水印） | 空态、加载占位统一调用，见 §5.2 |
| 网格 / 字号 | 8rpx 网格、9 级字号、`tabular-nums` | 触控热区 88rpx = 11 格，见 §6 |
| 深色切换 | `darkmode:true` + `theme.json` + `wx.setTabBarStyle` | 作为状态反馈的一致性约束，见 §5.6 |

### 0.2 五条核心判断（体验专家结论）

1. **tabBar 四栏按「时态 + 对象」切分，不按功能切分**：首页＝我的收藏快照（现在）、发行计划＝未来、全套清单＝全量目录（客观存在）、我的＝账本与账户（我的私有数据）。混放会造成「找一枚币到底去哪查」的首要迷路点。
2. **「加入藏品」必须就地闭环、不跳走**：详情是唯一自然的录入入口，登录只作为途中拦截，登录后应恢复原意图；否则用户会丢失检索上下文，这是本项目最高风险交互。
3. **「参考估值」标注必须与金额同屏、同视觉层级出现**，不能只放页脚免责声明。清单行、详情徽章、账本汇总三处是标注必现点；红绿变化值必须自带「较上次」四个字，否则应降级为中性文本。
4. **未知字段的可视化是产品可信度的第一触点**：`—` + 「暂无来源」+ 可追溯来源入口，比填入推定值更能建立信任。所有可选字段沿用现有 `wx:if` 不下发空壳。
5. **移除藏品是唯一必须二次确认的破坏性操作**；改数量 / 改成本是可逆的，用即时保存 + Toast 即可，不该打断用户。

## 1. 用户画像与核心任务场景（Jobs-to-be-done）

### 1.1 用户画像

| 画像 | 特征 | 关键诉求 | 设计含义 |
|---|---|---|---|
| **P1 建档收藏者**（主） | 已有实物，知道手里有几卷 / 几套，正在把线下收藏搬进小程序 | 快速录入、按套记数量与成本、看到账本汇总 | 录入路径要短；数量单位必须是「套 / 卷」而非预约限额 |
| **P2 查漏补缺者** | 关注某一套系，想知道「我还缺哪几枚」 | 系列进度 + 只看已收 / 只看缺、清单按系列过滤 | 清单默认露出「已收 X / 共 Y」，筛选一键可达 |
| **P3 预约跟进者** | 关注央行公告，发行日当天要去银行预约 | 下一枚倒计时、提醒我、公告来源可点开 | 计划页首屏就是「下一枚」；来源 MUST 可见可复制 |
| **P4 随手浏览者**（游客） | 未登录，只想看看有些什么、值多少 | 无门槛看图鉴与估值，不被登录墙挡住 | 目录 / 详情 / 计划全开放；登录墙只挡「写」操作 |
| **P5 数据审慎者** | 对网上估值不信任，关心数据来源 | 看到来源、时间、口径；区分官方估值与 AI 推理 | ⓘ 来源入口 + AI 分层 + 「参考估值」强制标注 |

### 1.2 核心任务场景（JTBD）

| # | Job 陈述 | 触发场景 | 成功标准 | 承载页面 |
|---|---|---|---|---|
| J1 | 当我拿到一枚新币，**我想把它记进我的账本**，以便知道我总共投入多少 | 刚兑换完、在整理藏品 | 从首页 / 清单进入详情 → 加入 → 回到原列表，≤ 4 次点击 | 详情 → 账户态 |
| J2 | 当我准备继续收集某个系列，**我想知道我还缺哪些**，以便安排下一次兑换 | 浏览系列、逛币市 | 系列进度一眼可见；清单「只看未收」可一键切换 | 首页系列区 / 清单 |
| J3 | 当我看到一枚币，**我想知道它大概值多少、这个数是怎么来的**，以便判断要不要收 | 详情 / 清单行 | 金额 + 参考估值标注 + 来源入口 + AI 价分层同屏可见 | 详情 |
| J4 | 当央行公布新计划，**我想在预约当天被提醒**，以免错过预约窗口 | 计划页、公告发布后 | 提醒按钮点击后明确回执「已设提醒 · 时间」；来源可复制 | 发行计划 |
| J5 | 当我想核对自己的收藏规模，**我想看到品种数 / 套数 / 参考市值**，以便对账 | 首页 / 我的 | 三个数字口径一致，且与网站端 holdings 相同 | 首页账本 / 我的 / holdings |

> 设计原则：J1/J2/J3/J5 都从**首页**或**清单**起步，因此这两页的信息密度与入口清晰度为最高优先级（P0）。

### 2.2 tabBar 四栏职责边界

| 栏位 | 回答的问题 | 时态 / 对象 | **做** | **不做**（避免越界） |
|---|---|---|---|---|
| 首页 | 我整体收得怎么样？最近有什么？从哪开始？ | 现在 · 我的概览 | 收藏快照、最新 3–5 条、Top 系列、登录引导 | 不放完整列表、不放筛选、不放编辑控件 |
| 发行计划 | 接下来发什么？什么时候预约？ | 未来 · 客观事件 | 倒计时、预约窗口、提醒订阅、公告来源 | 不放持仓编辑、不放估值主体、不放搜索 |
| 全套清单 | 某币存在吗？我收了没？还缺哪些？ | 全量 · 客观目录 | 搜索、筛选、系列切换、拥有态、行级估值 | 不做账本编辑（去详情 / holdings）、不放账本汇总 |
| 我的 | 我的账本明细与账号设置 | 现在 · 我的私有数据 | 汇总、holdings 入口、账户、关于、反馈 | 不做品种发现、不放最新发行、不放计划 |

**导航约定（防迷路）**：
- 所有 `tabBar` 页面之间只用 `wx.switchTab`，保证回退时栈干净；从 tab 页进入 detail / holdings / account 用 `wx.navigateTo`，保留返回路径。
- 详情页「同系列」弹层 → 详情用 `navigateTo`（同栈叠加），返回逐级，不用 `redirectTo`。
- 任一 Write 操作（加入 / 提醒 / 改数量）完成后**留在当前页**，不自动跳 tab。

### 2.3 与网站端窗格的对应关系

> 网站端实际 pane：`home / plan / all / series / holdings / coin / account / sitemap`（见 `public/index.html` 与 `public/app.js` 的 `showView`）。

| 网站 pane | 小程序对应 | 裁剪策略 | 备注 |
|---|---|---|---|
| `pane-home` | 首页 `index` | 保留 Hero + 账本快照 + 最新横滑 + Top 系列；去掉桌面端的全量统计图表 | 移动端只给「入口 + 结论」 |
| `pane-plan` | 发行计划 `plan` | 保留分组列表 + 状态徽章 + 提醒；桌面端宽表压缩为卡片行，详情收进底部弹层 | 来源标注必须保留 |
| `pane-all` | 全套清单 `list` | 保留搜索 / 筛选 / 排序 / 拥有态；桌面端多列属性表折叠为「主名 + meta + 右侧年份/估值」 | 筛选面板默认收起 |
| `pane-series` | 首页「按系列」区 + 独立 `series` 页 | 桌面端为顶层 tab，移动端降为首页区块 + 二级页，避免 tabBar 第五栏 | 从首页「全部 N 个 ›」进入 |
| `pane-holdings` | 我的 `mine` 的账本卡 + 独立 `holdings` 页 | 桌面端单页编辑表 → 移动端「分组折叠 + 左滑 / 长按编辑」 | 口径必须与网站一致（§8） |
| `pane-coin` | 详情 `detail` | 保留图集 / 价格 / 参数 / AI / 操作 / 介绍 / 同系列；桌面端表格式 facts 改两列网格 | AI 推理卡视觉分层不放宽 |
| `pane-account` | `mine` 的「账户与安全」→ `account` + `privacy` | 拆两步进入；微信一键登录优先，密码登录次选 | 隐私同意弹层为强制前置 |
| `pane-sitemap` | `more` / `about` | 移动端合并为「关于」+「更多」两个轻页 | 保留免责与联系方式 |

## 3. 关键页面布局规范

> 优先级定义：**P0** = 首屏必须出现 / 承载核心 Job；**P1** = 常驻但次要；**P2** = 可折叠或滚动后可见。
> 每页遵循「从上到下单一阅读流」，不使用多列并排（清单行内部除外）；左右安全边距统一 24rpx，底部 `calc(48rpx + env(safe-area-inset-bottom))`。

### 3.1 首页 `pages/index`

| 序 | 区块 | 内容与优先级 | 交互入口 | 状态 / 降级 |
|---|---|---|---|---|
| 1 | 品牌 Hero | P0：宋体「藏币录」+ 年份跨度 + 品种总数 + 分享；实物图或方孔圆钱水印 | 「分享给朋友」`open-type=share` | 无图 → 线稿水印；**不显示登录按钮**（不打断浏览） |
| 2 | 收藏账本浮层 | P0（已登录）：已藏 / 总数 + 进度条 + 面值/投入/市值/浮动四数 | 整卡点击 → `holdings` | 浮动值带 `.up/.down` 时必须同时显示「较上次」标注（§7.3）；游客 → 区块 2' |
| 2' | 游客引导卡 | P0（游客）：「登录后开始记你的藏品 / 与网页版同一账号」+ 主按钮 | 「登录 / 注册」→ `account` | 文案不承诺估值收益；按钮高 88rpx |
| 3 | 最新发行区 | P1：标题 + 「全部 ›」；横滑卡片（图 / 年份 / 名称 / 面额 / 估值行） | 卡片 → `detail`；「全部」→ 发行计划 tab | 无数据 → 隐藏整区（不显示空卡）；估值行必带「参考」字样 |
| 4 | 按系列区 | P1：标题 + 「全部 N 个 ›」；Top 系列网格（名称 / 已藏 X·共 Y / 进度条） | 卡片 → `list`（带 series 参数）；「全部」→ `series` | 无收藏时进度为 0，文案用「还没开始」，不用 0% 空进度 |
| 5 | 页脚 | P2：免责声明 + 联系微信（点击复制）+ 同步提示 | 联系微信 → 复制到剪贴板 + Toast | 免责声明常驻但不抢焦；同步失败提示 ≤ 两行 |

**线框要点**：Hero 与账本浮层保持 `-48rpx` 上叠关系；账本四数用 4 等分 + 1rpx 发丝分割线，键名 20rpx 用 `#6b6559`（承接 Phase 1 可读性修正），数值 `tabular-nums`；横滑卡露出下一张约 12% 宽度作为可滑动暗示。

**高风险**：账本四数口径与 `holdings` / 网站端必须完全一致（§8），否则用户会认为数据错乱。

### 3.2 全套清单 `pages/list`

| 序 | 区块 | 内容与优先级 | 交互入口 | 状态 / 降级 |
|---|---|---|---|---|
| 1 | 搜索行 | P0：假框（未激活）→ 真 input（激活）+ 清除 ✕；右侧「筛选」按钮带激活数角标 | 点击假框 → 激活焦点；输入实时过滤；筛选 → 展开面板 | 激活后 `cursor-spacing:24` 防键盘遮挡；清除保留筛选条件 |
| 2 | 系列胶囊 tab | P0：`scroll-view` 横滑；选中金色胶囊 | 点击切系列 | 超过一屏不换行、右侧渐隐暗示；切换后结果区回到顶部 |
| 3 | 结果计数条 | P1：「N 个品种 · 已收 M」+ 年份排序切换 | 「年份 ↓/↑」→ 重排 | 计数随筛选实时更新，不用动画数字滚动 |
| 4 | 筛选面板 | P1（默认收起）：年份 / 面额 / 材质 picker +「只看已收」+「清除」 | 选择即生效；「清除」仅清额外条件，不清关键词 | 有筛选时角标显示数量；面板展开时结果区不被遮挡（流式占据高度） |
| 5 | 结果行列表 | P0：缩略图 / 名称 +「已收」标签 / meta / 发行量·套系 / 右侧年份 + 估值 | 行 → `detail` | 无图 → 占位水印；无估值 → 显示「—」+ 无「参考价」行（不编造） |
| 6 | 空态 | 条件态：区分「只看已收」与「关键词无匹配」两种文案 | 空态内提示取消筛选 | 方孔圆钱线稿水印 120rpx / 透明度 0.2 |

**线框要点**：搜索假框是关键——避免机型自动聚焦弹键盘遮挡首屏（现有实现已正确，保留）；筛选面板用流式展开而非覆盖层，避免「筛选后看不到结果」。

**高风险**：搜索实时过滤 + 输入中文时容易触发 repeatedly 重排；建议 `bindinput` 防抖 ≥ 200ms，结果计数在防抖后更新。

### 3.3 发行计划 `pages/plan`

| 序 | 区块 | 内容与优先级 | 交互入口 | 状态 / 降级 |
|---|---|---|---|---|
| 1 | 页头 | P0：标题 + 来源名 + 提醒机制说明（「预约当天 09:00 微信通知；每次授权只发一条」） | 来源名可点击查看来源 | 说明文案必须前置，不能等用户点了才告知「只发一条」 |
| 2 | 下一枚提醒条 | P0：标签「下一枚」+ 简称 + 发行日 + 倒计时 | 整条 → 打开该项计划弹层 | 无未来项 → 隐藏此条；倒计时为 0 时文案改「今日发行」 |
| 3 | 年份分组标题 | P1：`YYYY 年 · 计划 N 项 · 增发 M · 已发 K` | 无 | 数字 `tabular-nums`；「增发」用警示色文字，不用红绿 |
| 4 | 计划项行 | P0：名称 / 类型·面额·发行量·备注 / 右侧状态徽章（预约中 / 即将 / 已结束）+ 日期 + 预约·兑换·倒计时 +「提醒我」 | 行 → 计划详情弹层；「提醒我」`catchtap` 独立响应 | 无来源的发行量显示「—」；「提醒我」仅对未发行项渲染 |

## 4. 核心交互流程

> 图示约定：`→` 正常流，`⇢` 分支，`✕` 异常 / 中断。每流包含「步骤 / 状态 / 反馈 / 异常分支」。

### 4.1 流程 ① 登录 / 游客态

```text
游客浏览（目录/详情/计划全部可读）
   → 触发写操作（加入藏品 / 绑定 / 设置密码）
   → 拦截：跳转 account（保留来源页与待处理意图）
   → 选择：微信一键登录 ⇢ 账号密码登录/注册
   → 隐私同意（未勾选 → 阻止提交 + 就近提示，不用 Toast 一闪而过）
   → 提交中：按钮 loading，禁用重复点击
   → 成功：Toast「登录成功」→ 微信登录首启弹「设置头像昵称」（可跳过）
   → 返回来源页 ✕ 若来源页已不在栈中 → 回首页，并提示「已登录，可继续记藏品」
✕ 失败：密码错 / 用户名占用 / 网络超时 → 表单内错误文案聚焦字段，不清空已输入
✕ 用户放弃：返回来源页，游客态不变，不反复弹登录
```

| 状态 | 反馈 |
|---|---|
| 未登录浏览 | 无登录墙、无诱导弹窗；仅写操作处显示「登录后加入」 |
| 提交中 | 按钮 `loading` + 禁用 |
| 成功 | Toast ≤ 2s + 页面回到原上下文 |
| 失败 | 字段级错误 + `aria-live` 区域朗读（见 §6.4） |

### 4.2 流程 ② 标记拥有 / 录入持仓（**最高风险**）

```text
入口 A：详情「加入我的藏品」
入口 B：清单 / 系列中无直接加入 → 先进详情（保持单一录入口，避免口径分叉）
   → 游客？ ⇢ 是 → §4.1 登录拦截 → 成功后自动回填本页意图，仍需用户再点一次确认（不静默写入）
   → 点击「加入我的藏品」→ loading（防重复）
   → 成功：按钮变为「已收」标记 + Toast「已加入我的藏品」+ 账本数字刷新
       ✕ 不在页面跳走；用户可继续点「纠错反馈」等
   → 后续编辑：进 holdings → 左滑 / 长按 → 弹层改「数量（套/卷）」「每套成本」
       → 保存 → Toast「已保存」→ 关闭弹层，行内数据就地更新
   → 移出：→ 二次确认弹层（说明影响）→ 确认 → Toast「已移出」→ 行移除 + 汇总刷新
✕ 网络失败：保留本地输入，Toast「保存失败，已保留你的填写，重试？」+ 重试按钮
✕ 并发冲突（网站端已改）：提示「数据已在其他设备更新，请刷新」，刷新后回填，不覆盖
```

| 关键点 | 规范 |
|---|---|
| 数量单位 | 步进器单位跟随品种：`卷 / 套 / 张 / 枚`，与 `setSizeBase` 实物成套口径一致（§8） |
| 成本口径 | 输入「每套成本」而非总价；明确提示「只影响你的账本，不会改全站参考价」 |
| 可逆性 | 加入 / 改数量 / 改成本都可逆、无需确认；仅移出需确认 |
| 意图恢复 | 登录后回原详情页；**不静默加入**——用户重新点一次，避免误写（Nielsen #5 错误预防） |

### 4.3 流程 ③ 搜索筛选

```text
点击搜索假框 → 渲染真 input + 聚焦（键盘弹起，页面不被顶出可视区）
   → 输入（防抖 ≥200ms）→ 结果实时过滤 → 计数条更新
   → 点「筛选」→ 面板流式展开 → 选年份 / 面额 / 材质 / 只看已收
       → 角标显示生效条件数
   → 点系列胶囊 → 结果切系列 + 列表回到顶部
   → 点「年份 ↓/↑」→ 重排，排序状态可见
   → 点清除 ✕ → 清关键词；「清除」按钮 → 清额外筛选（两者互不干扰）
   → 点击行 → detail
✕ 0 结果：区分文案——只看已收 → 「还没有收藏到符合条件的东西，先取消『只看已收』试试」；
            关键词无匹配 → 「没有匹配的品种，换个关键词试试」；均带方孔圆钱水印
✕ 输入中被键盘遮挡：cursor-spacing 已设；长列表滚动时 input 保持可见或收起键盘
```

### 4.4 流程 ④ 发行计划订阅提醒

```text
进入计划页 → 前置说明「预约当天 09:00 微信通知（每次授权只发一条）」
   → 找到未发行项 → 点「提醒我」（catchtap，不触发行点击）
   → 调用 wx.requestSubscribeMessage（订阅消息授权）
       → 同意 → 记录提醒时间 → 按钮变「已设提醒」+ 显示具体时间
                → Toast「已设提醒：X月X日 09:00」
       ✕ 拒绝授权 → 按钮保持「提醒我」→ 轻提示「未开启通知，你仍可查看计划；
                    可在『设置-通知』重新允许」→ 提供「复制公告链接」兜底
       ✕ 系统通知总开关关闭 → 引导去系统设置，不反复弹授权
   → 到期：微信服务通知送达（一条）→ 点击 → 打开计划页并定位到该项
✕ 计划变更 / 取消：已设提醒项状态失效 → 行内标注「计划有变，请以最新公告为准」+ 来源入口
```

| 约束 | 说明 |
|---|---|
| 授权诚实 | 「每次授权只发一条」必须在点击**之前**可见，不能事后告知 |
| 兜底 | 拒绝授权后仍保留「复制公告链接」，用户可自行关注 |
| 幂等 | 重复点「提醒我」不重复订阅；已设状态显示时间 |

### 4.5 流程 ⑤ 详情页参考估值与 AI 价的信息呈现顺序

> **强制顺序（不可调换）**：名称 → 官方参考估值徽章 → 套系进度 → 参数 → AI 推理价卡 → 操作 → 来源。

| 层级 | 元素 | 呈现规范 | 禁止 |
|---|---|---|---|
| L1 金额主体 | `¥{{unitPrice}} / {{unitLabel}}` | `--cl-price-main` 中性权威金、`fs-2xl`、`tabular-nums` | 红 / 绿、K 线、分时图隐喻 |
| L2 强制标注 | 金额**紧邻下方**：`参考估值 · 非实际成交价` | `fs-xs` `--cl-text-dim`，与金额同屏、不可省略 | 只放页脚、写「参考价」后无下文 |
| L3 套系换算 | `一套{{setSizeText}} ≈ ¥{{setPrice}}`（若有） | 同语气的 `≈`，沿用 L2 标注覆盖 | 把 `≈` 写成 `=` |
| L4 变化值 | `↑2.3% 较上次估值` | 仅此处用 `--cl-up / --cl-down`；**必须**含「较上次」 | 无标注的裸红绿数字 |
| L5 AI 推理价 | 独立浅底卡：`AI 推理` 深色徽章 + 金额 + `按发行量·材质·年代推算，面值已按年化 2.5% 通胀折算` + `仅供参考` | 与官方估值**视觉分层**、不并列同款 | 两价并排同字号同底色、去掉假设说明 |
| L6 来源 | ⓘ 入口 → 来源名 / 更新时间 / 公告链接 | 无来源则该字段留空或 `—`，不写「推测」伪装成事实 | 编造来源、空 ⓘ 点了没内容 |

**状态**：估值缺失 → 整块价格徽章不渲染，参数区对应字段显示 `—`；AI 价缺失 → 整卡隐藏，不留空卡。
**反馈**：点 ⓘ → 底部弹层展示来源与口径；点 AI 卡的「仅供参考」→ 展开假设说明（默认已展示一行，不再折叠关键免责）。

### 4.6 高风险交互与降级方案

| 风险 | 表现 | 降级方案 |
|---|---|---|
| 登录打断写入 | 用户填了一半被跳走，回来后上下文丢失 | 保留来源页栈 + 待处理意图；登录后回原页，重新确认才写入 |
| 左滑 vs 返回手势 | holdings 左滑编辑与系统侧滑返回冲突 | 仅卡片区域响应、阈值 ≥ 64rpx；**长按为等价兜底**，提示条常驻说明 |
| 提醒嵌套点击 | 「提醒我」在行内触发详情弹层 | `catchtap` 独立响应；行其余区域 `bindtap` |
| 键盘遮挡输入 | 搜索 / 成本输入被键盘盖住 | `cursor-spacing:24`；输入时滚动 Container；搜索用假框防自动聚焦 |
| 估值过期 | 离线或缓存旧估值被当成当前价 | 显示数据日期 + 「参考估值」；过期超阈值加「数据可能已更新」提示 |
| 主题切换不同步 | 页面变色但原生 tabBar 未变 | `wx.onThemeChange` + `wx.setTabBarStyle` 同步（承接 Phase 1 §7.4） |
| 字体放大截断 | 系统大字体下按钮 / 徽章文字裁切 | 文本容器用 `min-height` 不写死高度；允许两行；超限省略号 + 详情可见全文 |
| 深链失效 | 分享 / 通知打开已下架品种 | 统一「没找到这个品种」空态 + 返回首页按钮 |

## 5. 状态与反馈规范

### 5.1 加载态

| 场景 | 形式 | 规范 |
|---|---|---|
| 首屏目录（内置，无需请求） | **不用骨架**，直出 | 品种目录内置，本地读取 < 100ms；显示骨架反而制造等待感 |
| 账本 / 汇总数据（网络） | 骨架屏 | 复用最终布局的灰底块（面值 / 投入 / 市值 / 浮动四块），不带闪烁动画；数值区显示 `—` 不是 `¥0` |
| 列表图片 | 占位 | 方孔圆钱线稿水印（透明度 0.15）+ 浅底，加载完成淡入 ≤ 200ms |
| 提交操作 | 按钮 `loading` + 禁用 | 用 `loading` 属性，不用全屏遮罩；同时防重复点击 |
| 下拉刷新 | 原生 `enablePullDownRefresh` | 刷新图标金色 `--cl-brand`；只刷新网络数据（ holdings / 计划 / 估值），目录不动 |

> 减少动画偏好开启时：淡入去除、骨架静止、进度条直接到值（§6.3）。

### 5.2 空态

统一结构：**方孔圆钱线稿水印（120rpx，透明度 0.2）→ 主文案 → 辅助文案 → 可选主按钮**。承接 Phase 1 §6.9。

| 页面 | 主文案 | 辅助 / 按钮 |
|---|---|---|
| 首页账本（游客） | 登录后开始记你的藏品 | 与网页版同一账号 ·「登录 / 注册」 |
| 我的 / holdings（空账本） | 还没有藏品 | 挑第一枚，开始记录你的收藏 ·「去全套清单」 |
| 清单（筛选无果） | 没有匹配的品种 | 换个关键词试试 / 取消「只看已收」 |
| 计划（无数据） | 暂无可用的发行计划数据 | 保留页脚来源声明（不能空得没有解释） |
| 详情（未找到） | 没找到这个品种 | 返回上一页 |
| 详情（无图） | 暂无实拍图 | 线稿水印占位，不用 broken image |
| 任意列表无来源字段 | `—` | 就近「暂无来源」，不用 `0`、不用推定值 |

### 5.3 错误态

| 级别 | 场景 | 呈现 |
|---|---|---|
| 字段级 | 密码格式、用户名占用 | 字段下方 24rpx `--cl-danger` 文案，聚焦出错字段 |
| 轻提示 | 复制成功、保存成功、网络抖动 | Toast ≤ 2s，居中，不阻断操作 |
| 页面级 | 数据加载失败 | 页面内错误卡 +「重试」按钮；保留已加载的目录内容，不全屏白屏 |
| 阻断 | 隐私未同意 | 就近提示 + 弹层内「同意并继续」，不用一闪而过的 Toast |
| 静默失败禁止 | 订阅拒绝、登录失败 | 必须给可见反馈 + 下一步出口，不允许点了没反应 |

### 5.4 成功态

- 加入藏品：按钮就地变「已收」+ Toast + 汇总数字刷新（就地反馈优于跳页）。
- 保存成本 / 数量：Toast「已保存」+ 弹层关闭 + 行内数据更新。
- 设置提醒：按钮变「已设提醒」+ 显示具体时间（状态可见，Nielsen #1）。
- 复制内容：Toast「已复制」，来源链接复制后提示「可粘贴到浏览器查看公告」。

### 5.5 触屏 hover 反馈

- 所有可点击 `view` 沿用 `hover-class="tap-hover"`；主按钮用内置 hover 加深至 `--cl-brand-700`。
- hover 态变化仅限背景 / 透明度，**不做位移缩放**（避免误触与眩晕）。
- 点击热区 ≥ 88rpx（§6.1）；视觉尺寸可小于热区，用透明 padding 扩展。
- 禁用态：灰底 + 透明度 0.6 + 移除 hover + `aria-disabled` 语义。

### 5.6 破坏性操作二次确认

| 操作 | 确认文案要素 | 确认按钮 |
|---|---|---|
| 从我的藏品移出 | 名称 + 「移出后账本记录会删除，参考估值不受影响」 | 「移出」用 `--cl-danger` 文字，次按钮「取消」为默认焦点 |
| 退出登录 | 「退出后本机的账本缓存将清除，云端数据仍在」 | 「退出登录」次按钮样式 |
| 清除筛选 | **不需要**确认（可逆、无损失） | — |

> 确认弹层用系统 `wx.showModal` 时，标题写动作、内容写影响，`confirmText` 用具体动词（「移出」而非「确定」）。

### 5.7 Nielsen 启发式对照（自检清单）

## 6. 可访问性与触控标准

### 6.1 触控热区

| 元素 | 最小热区 | 说明 |
|---|---|---|
| 所有可点击 view / button | **88 × 88rpx**（= 44pt @375pt） | 视觉可小于热区，透明 padding 补足 |
| 步进器 `− / +`、提醒按钮、chip、关闭 ✕ | 88rpx | 关闭 ✕ 常见踩坑，必须补足 |
| 列表行 | 高度 ≥ 120rpx | 行内热区不重叠 |
| 胶囊 tab / 系列卡 | 高度 ≥ 88rpx | 横滑区需留间距防误滑 |
| 相邻热区间距 | ≥ 16rpx | 防误触 |

### 6.2 对比度（承接 Phase 1）

| 内容 | 要求 | 令牌 |
|---|---|---|
| 正文 / 关键数值 | ≥ 4.5:1 | `--cl-text` / `--cl-neutral-900` |
| 大号标题（≥ 36rpx 或 22px 加粗） | ≥ 3:1 | `--cl-text-strong` |
| **需阅读的辅助文字** | ≥ 4.5:1（≈5.7:1） | **`#6b6559`（`--cl-neutral-650`）** |
| 弱化角标 / 页脚（非关键） | 可用 `#8a8378`，但不得承载必要信息 | `--cl-text-muted` |
| 浅底金字小号 | 用 `--cl-brand-700 #7a541a`（4.6:1 边界上更安全） | 不用 `#9a6b1f` 渲染小号正文 |
| 涨跌色 | 红 / 绿文字需 ≥ 4.5:1；深色模式用提亮值 | `--cl-up / --cl-down` 按皮肤 |
| 非文本控件（描边 / 进度槽 / 焦点圈） | ≥ 3:1 或与背景明显区分 | `--cl-border-base` / `--cl-shadow-focus` |
| **红绿不得作为唯一信息载体** | 变化值必须有箭头 + 「较上次」文字 | §7.4 |

### 6.3 字号缩放与减少动画

| 项 | 规范 |
|---|---|
| 字号缩放 | 数字与关键金额用 `tabular-nums` + 弹性容器；检测系统字体缩放后按 `≤1.3×` 放大正文，超出用「查看大图 / 详情全文」兜底，不高位截断 |
| 文本容器 | 用 `min-height` 而非固定 `height`；按钮文字允许两行；`line-height` 按 Phase 1 阶梯 |
| 减少动画 | 尊重系统「减少动态效果」偏好（基础库支持则读 `reducedMotion`，否则在「更多」提供手动开关）：关闭淡入 / 骨架闪烁 / 进度条动画 / 方孔旋转，仅保留状态瞬时切换 |
| 动画上限 | 任何装饰动画 ≤ 600ms，不循环（承接 Phase 1 §5.1） |

### 6.4 屏幕阅读器标签建议

> 小程序组件支持 `aria-label` / `aria-role`（具体基础库版本以端能力为准，低版本退化为可读邻近文本）。

| 组件 | 建议标签 |
|---|---|
| 藏品缩略图 / 行 | `aria-label="{{name}}，{{year}}年，{{face}}元，{{owned?'已收藏':'未收藏'}}"` |
| 价格徽章 | `aria-label="参考估值 {{unitPrice}} 元每{{unitLabel}}，非实际成交价"`（把标注读出来） |
| 变化值 | `aria-label="较上次估值上涨 2.3%"`（读语义不读颜色） |
| 提醒按钮 | `aria-label="为{{name}}设置预约提醒"` / 已设时 `aria-label="已设置提醒，{{time}}"` |
| 步进器 | `aria-label="减少数量"` / `aria-label="增加数量，当前 {{rolls}} {{unitWord}}"` |
| 关闭 ✕ | `aria-label="关闭弹层"` |
| 空数据字段 | `aria-label="暂无来源数据"` 而非读空字符串 |
| 错误提示区 | 容器加 `aria-live="polite"`，读屏即时播报字段错误 |

### 6.5 键盘 / 焦点顺序（外接键盘与无障碍）

- 阅读与焦点顺序 = 视觉从上到下顺序：图 → 标题 → 价格 → 操作 → 详情。
- 弹层打开时焦点语义上进入弹层，关闭后回到触发按钮；遮罩层阻止背景点击（`catchtouchmove=noop` 已实现）。
- `open-type` 按钮（分享 / 选择头像）保留原生语义，不用 `view` 模拟。
- 表单 `confirm-type` 串联：用户名 `next` → 密码 `done/next` → 确认密码 `done`（现有实现正确）。

## 7. 数据呈现的诚信规范

### 7.1 三条铁律

1. **来源可追溯**：发行量 / 面额 / 发行计划必须有来源；详情「发行信息」区展示 `descSrc`，计划页展示来源名 + 公告链接。
2. **未知不编造**：拿不到就留空或 `—`；不写「约」「大概」伪装成事实，不填推定值。
3. **估值非行情**：所有金额都是「参考估值」，红绿只用于「较上次变化」。

### 7.2 无来源字段的呈现方式

| 字段状态 | 呈现 | 禁止 |
|---|---|---|
| 有值 + 有来源 | 值 + ⓘ 来源入口（点开看来源名 / 时间 / 链接） | — |
| 有值 + 无来源 | 值 + 就近「暂无来源」灰色小字（`--cl-text-dim`） | 假装官方、加 ⓘ 空弹层 |
| 无值 | `—`（em dash），整行保留以维持布局 | `0`、`无`、`待定`（若无官方待定语义）、空字符串占位 |
| 官方明确「待定」 | `待定`（计划页日期字段已用此口径） | 估算日期冒充确定 |
| 推定 / 推算值 | 只在 AI 卡内出现，带「AI 推理 / 仅供参考 / 假设说明」 | 混入官方参数 facts 区 |

- 所有可选字段继续使用 `wx:if` 条件渲染：`wx:if` 为假时**整块不渲染**，不留下空壳标题（现有页面已正确，保持）。

### 7.3 强制标注层级（必现点）

| 位置 | 必须出现 | 文案 |
|---|---|---|
| 详情价格徽章 | 金额下方固定一行 | `参考估值 · 非实际成交价` |
| 清单结果行估值 | 行内估值旁或统一列头说明 | `参考`（简版，列表空间有限） |
| 首页账本四数 / 我的 / holdings 汇总 | 市值区就近说明 | `参考市值` + 页脚 `价格数据为参考估算，不构成投资建议` |
| AI 推理价卡 | 卡内 | `仅供参考` + 假设说明 |
| 发行计划 | 页头 + 页脚 | 来源名 + `以发行前公告为准` |

> 当前 `detail.wxml` 的 `pb-tip` 仅写「参考价」，需升级为完整文案；这是 Phase 1 强制标注机制在体验层的落地要求。

### 7.4 涨红跌绿的交互约束

| 允许 | 禁止 |
|---|---|
| `↑2.3% 较上次估值`（带箭头 + 文字 + 标注） | 裸红 / 绿金额 |
| 账本盈亏在明确「较上次」语境下用色 | 用红绿渲染 `¥` 金额主体 |
| 深色模式用提亮红 `#FF6B5A` / 绿 `#3DDC97` | 计划状态徽章用红绿（改金 / 浅 / 灰） |
| 色弱兜底：箭头 + 文字 + 标注三重编码 | 仅靠颜色区分涨跌 |

- 若某处无法附加「较上次」标注（如缺乏上一期数据），**该处一律降级为中性金色文本**，不使用红绿。
- 「增发」「待定」「草稿」等非价格状态用 `--cl-warning` 琥珀，不借红绿语义。

## 8. 双端一致性对照表

### 8.1 页面 ↔ 窗格 ↔ 口径

| 小程序页面 | 网站 pane | 共享数据 | 共享算法 / 口径 | 一致性校验点 |
|---|---|---|---|---|
| 首页 `index` | `home` | `coins.json`, holdings | `calc()` → face/cost/market/rolls/kinds；`pct()` | 四数必须与 holdings / 网站完全相同 |
| 发行计划 `plan` | `plan` | `plan.json` | 状态判定（预约中 / 即将 / 已结束）、`limitText` | 来源名、倒计时口径一致 |
| 全套清单 `list` | `all` | `coins.json`, `series.json`, holdings | `unitPrice()`, `setSizeOf()` 展示一套件数 | 行级估值与详情一致 |
| 系列 `series` | `series` | `series.json`, holdings | 进度 = 已收品种 / 系列总数 | 首页 Top 系列与系列页进度一致 |
| 详情 `detail` | `coin` | `coins.json`, `descriptions.json`, `gallery.json` | `unitPrice()`, `setPriceOf()`, AI 推理 `aiLine()` | 金额 / AI / 来源三处同口径 |
| 我的 `mine` + `holdings` | `holdings` | holdings（云端） | **`setSizeBase()` 实物成套**、`calc()` | 数量单位、成本、盈亏一致 |
| 账户 `account` | `account` | 用户 / 权限 | 同一账号，微信绑定互通 | 网站设密码后小程序可登录，反之亦然 |
| `about` / `more` / `feedback` | `sitemap` + 页脚 | 静态文案 | 免责声明文案统一 | 免责表述一致 |

### 8.2 关键算法口径（两端必须同源）

| 函数 / 字段 | 定义 | 移动端使用位置 | 注意 |
|---|---|---|---|
| `unitPrice(d)` | `{face: d.face, est: d.est}` | 清单行估值、详情金额主体 | `est` 为**单件参考估值**，非成交价 |
| `setSizeOf(d)` | `setSize`（管理端显式） > `limit`（央行预约限额） > `setSizeBase` | **清单 / 详情「一套 ≈ ¥」展示口径** | 展示口径含预约限额，见待确认 Q1 |
| `setSizeBase(d)` | `setSize` > 套系声明件数 > 20 | **账号 holdings 实物成套录入口径** | 与用户「按实物成套、不用预约限额」一致 |
| `setPriceOf(d)` | `{size, face: face×size, est: est×size}` | 详情套系换算 | `≈` 不是 `=` |
| `calc()` | 按持仓累计 face / cost / market / rolls / kinds | 首页账本、我的、holdings 汇总 | 三处同源，禁止各页自算 |
| `pct(n)` | 保留 1 位小数 + `%` | 所有进度条文字 | — |
| `aiLine()` | 单枚理论价 × 件数；面值按年化 2.5% 通胀折算 | 详情 AI 卡、holdings 行 AI 价 | 假设说明必须随卡展示 |

> **口径分叉警示**：展示口径 `setSizeOf`（限额优先）与账本口径 `setSizeBase`（实物成套）是两套不同定义，移动端必须在 UI 文案上区分「一套 ≈（展示）」与「持有 N 套/卷（账本）」，避免用户拿预约限额当自己实际拥有的件数。
